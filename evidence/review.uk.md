# Перевірка роботи

25 жовтня 2026 року перевірено код, результати запусків і файли для здачі.

## Відповідність завданню

- Таблиця створюється у власній схемі через CREATE TABLE IF NOT EXISTS. У MySQL перевірено чотири потрібні поля, primary key та auto increment.
- Окремий PythonOperator обирає медаль через random.choice.
- BranchPythonOperator запускає одну гілку. В усіх 6 запусках одна count task має success, дві інші — skipped.
- Три count tasks рахують відповідні медалі й записують результати у власну таблицю. Кількості збігаються з CSV і SQL GROUP BY.
- PythonOperator виконує time.sleep з паузою 5 або 35 секунд. Правило none_failed_min_one_success дозволяє продовжити після успішної гілки, навіть якщо дві інші пропущено.
- SqlSensor перевіряє UTC-час рядка за id із XCom поточного запуску. Перевірка успішна при віці близько 5 секунд і завершується failed при 35.063458 секунди.

## Результати перевірок

Airflow 2.11.2, MySQL provider 6.5.0, common-sql 1.32.0 і mysql-connector-python 9.6.0 встановлені без конфліктів залежностей. DagBag завантажує 8 завдань без помилок імпорту. Повторно пройшли 8 mock-тестів. Усі Python-файли завантажуються синтаксичним аналізатором.

Виявлено помилку округлення на межі 30.000001 секунди. Після заміни SQL-ділення на цілі мікросекунди значення 30000001 відхиляється і в mock-тесті, і в MySQL.

Окрема перевірка запитами лише на читання підтвердила контрольну суму CSV, 316834 вихідні рядки, кількості медалей, версію MySQL 8.4.11, усі 6 рядків результатів, структуру таблиці, стани завдань і XCom id 1..6. Параметри sensor відповідають id і медалі кожного запуску. Журнал Airflow містить ті самі результати. Після виправлення округлення розбіжностей не знайдено.

## Межі перевірки

Запуски виконано через dag.test: SQL, sleep та завдання Airflow працювали в одному процесі. Scheduler/executor, паралельне виконання й примусове застосування timeout не перевірялися. Поля start_date/duration окремих task instances можуть бути NULL; тривалість підтверджують час початку й завершення запусків та журнал. Попередження про scheduler видно на скриншотах.

Джерело — локальна проєкція поля medal публічного CSV. Тотожність віддаленому набору даних GoIT не перевірялася. Скрипти підготовки розраховані лише на власний ізольований MySQL.

## Файли для здачі

Переглянуто 5 скриншотів і PDF-документ. Зображення в HTML відповідають оригінальним файлам. Виправлено відображення позначення `<workspace>` у тексті документа.

Перед публікацією перевіряються всі підготовлені файли й ZIP: цілісність архіву, відповідність вмісту, відсутність паролів і зайвих файлів. Результати записано в evidence/package-check.json. Підтвердження публікації, контрольна сума архіву й commit збережені локально окремо.

До репозиторію й архіву не входять .env, credentials, venv, runtime, MySQL data/binaries, CSV, metadata DB, кеші, .git або файли доставки до sandbox. Для здачі потрібно додати ZIP і посилання на репозиторій у LMS.
