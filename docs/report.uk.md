# Домашня робота 7 Apache Airflow

Григорова Ауріка Вадимівна

## Поточний результат

Підготовлено DAG `aurika_hw07_medals`. Він створює власну таблицю, випадково обирає медаль, запускає одну із трьох гілок підрахунку, чекає заданий час і перевіряє свіжість запису стандартним SqlSensor.

**Робота поки не готова до здачі.** Відсутнє підтверджене навчальне MySQL-підключення та дозвіл на особисту схему. Справжній success run і run із затримкою 35 секунд не виконані. Скриншоти таблиці й Airflow UI ще не отримані. Публікації GitHub не було.

## Що реалізовано

Таблиця містить id з auto increment і primary key, medal_type, count та created_at. Count tasks читають `olympic_dataset.athlete_event_results`, але записують лише у власну таблицю. Час зберігається в UTC.

Join після branching використовує `none_failed_min_one_success`. Sensor читає id поточного run з XCom. Він не може пройти через свіжий рядок іншого run. Одночасно дозволено один run. При віці понад 30 секунд sensor завершується failed; відсутній або майбутній запис також дає failure. Для очікування встановлено обмеження.

## Що перевірено

Python 3.12.4, Airflow 2.11.2, MySQL provider 6.5.0 та common-sql 1.32.0. `pip check` не знайшов несумісних залежностей. DagBag завантажив 8 tasks без import errors. Пройшли 8 локальних тестів, включно з межами 30 секунд і failure для 35 секунд.

Відповіді БД у цих тестах підставлені. Це перевірка коду, а не доказ справжнього підрахунку чи виконання DAG на MySQL.

## Що залишилося

Підключити дозволене навчальне середовище. Виконати success run з 5 секундами та негативний run із 35 секундами. Додати справжні скриншоти таблиці, Graph/Grid обох runs і sensor log з failed. Повторити review, підготувати остаточний архів, опублікувати власний навчальний repo та звірити remote SHA. Здачу до LMS користувачка виконує сама.
